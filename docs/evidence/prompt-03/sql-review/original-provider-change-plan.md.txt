- One SELECT policy on the existing `auth.sessions` table, `mc_staff_current_session`, and column-level SELECT for the executor. This touches Supabase-managed Auth schema; check support and compatibility before use. It limits reads to `auth.uid()` and JWT `session_id` and is needed to deny revoked sessions immediately; merely verifying a JWT does not establish session revocation.

Role changes require a separate privileged owner procedure and are not exposed by this application.
- A record insertion and audit insert occur in one transaction. No update or delete interface is offered. The gate limits sessions to 30 minutes idle and eight hours total. A revoked session is denied when the corresponding `auth.sessions` row no longer exists. The gate stores last activity in Postgres, so server restart does not extend a session.
